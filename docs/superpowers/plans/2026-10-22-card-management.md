# 寻迹事项管理实施计划

> For agentic workers: use executing-plans to implement locally, task by task. No GitHub push unless the user explicitly asks again.

**Goal:** 补齐不加入待办、忽略恢复、直接新建、编辑、删除恢复和完整查询。
**Architecture:** 延续原生 Java + SQLite + WebView；数据库原位迁移保存用户修改标记、原提取标题和删除前状态。重算按原提取标题匹配；有用户保护记录无法可靠匹配时保留该来源全部现有卡片，避免误覆盖和复活。
**Tech Stack:** Java, Android SQLite, HTML/CSS/JS, Playwright.
**Spec:** 用户已确认本聊天 Q1、Q2；不上传 GitHub。

## 约束与界面
- 原文不可被编辑卡片覆盖；手动新建无需 AI 密钥；新建默认待办。
- 不加入待办进入已忽略，可恢复收件箱；删除进入回收站，可恢复到删除前状态，无永久清空入口。
- 原蓝白系统保留：底色 #f5f7fc、纸面 #fff、主色 #275bdd、文字 #19243d、次要文字 #596781、分隔 #e3e8f1。系统中文字体，正文16px，48px操作触达，左对齐，长题干自然换行。
- 收件箱主操作为加入待办，旁设不加入待办；编辑/删除通过更多进入；上方入口切换待确认/已忽略/回收站。保持四个底部导航。
- 已忽略/回收站均支持搜索和分类；搜索补充要求与截止时间。手动编辑表单有标签、校验、取消、未保存离开确认。

## Review Focus
- 同一原文多卡，删除一张不得删除其他卡或原文。
- 手动修改标题后重新提取不能覆盖，标题变化不能使已忽略/删除事项复活。
- 旧数据库升级不丢失记录；手动新建来源不得进入自动提取队列。
- 回收站恢复已完成/忽略/待办卡片时状态正确；非法转换和无效ID显示失败。
- 320px、横屏、大字号、键盘和长输入保持可操作；失败不能虚报已保存。
