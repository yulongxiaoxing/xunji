# 完整运行教程与示例

本教程对应寻迹v0.36交付版（Android versionCode 37）。先跑通本地流程，再按需打开AI和QQ接入，不必第一次就同时配置所有环境。

下载：[APK](https://github.com/yulongxiaoxing/xunji/releases/download/v0.36/Xunji-v0.36.apk) · [完整交付包](https://github.com/yulongxiaoxing/xunji/releases/download/v0.36/Xunji-v0.36-delivery.zip) · [项目说明](https://github.com/yulongxiaoxing/xunji#readme)

## 一、选择运行方式

| 方式 | 需要什么 | 可体验的流程 |
| --- | --- | --- |
| 本地体验 | Android 9及以上手机、APK | 新建事项→今日→周/月日程→编辑/完成 |
| AI体验 | 本地体验+网络+个人DeepSeek API密钥 | 口头记忆→预览→待办；粘贴通知→收件箱→决定→日程 |
| QQ完整体验 | AI体验+Windows电脑+Python 3+ADB+NapCat+USB调试 | 指定群新通知→原文→AI→玻璃收件箱→待办→日程 |

不使用电脑接入时，本地事项和已导入课表仍能使用。APK没有内置开发者的账号、密钥或个人数据。

## 二、安装并跑通第一条日程

1. 下载APK，传到手机打开，按系统提示允许本次安装；打开应用“寻迹”。
2. 在“今日”点击“新建事项”，选择“活动”。
3. 填写：名称“【演示】图像视觉培训会”，地点“实验楼201”，日期 **2026-10-26**，开始 **10:30**，结束 **12:00**。要求可写“提前十分钟到场，携带电脑”。
4. 点击“创建待办”。回到今日，可在对应日期框看到安排。
5. 点底部“日程”，将日期选为 **2026-10-26**，查看周视图中的10:30—12:00区间，再切到月视图查看26日内容。

**跑通标志**：创建成功，有明确日期和起止区间，周表与月表均能找到同一事项。手动新建直接创建待办，不经过待确认收件箱。

同签名的交付版本可以覆盖安装。新电脑自行构建会生成不同签名，不能覆盖交付APK；不要卸载有真实数据的应用或清空数据库来强行安装。

## 三、使用自然语言整理

1. 在“信息与待办→设置→DeepSeek”填写自己的API密钥，点“保存密钥”。创建密钥的入口见项目README。不要把密钥发到群里或录入视频。
2. 打开“今日→口头记忆”，复制输入：

```text
我明天上午八点半到十一点半有一个图像视觉部的培训会。
```

3. 点“DeepSeek整理”，等待预览。核对：分类为活动，名称为图像视觉部培训会，日期为**实际次日**，时间为08:30—11:30。
4. 预览正确后确认加入，再在对应日期的日程查看。

口头记忆是文字入口，语音可用手机系统输入法完成；应用没有“开始录音”按钮。输入法识别后的文字也要先核对。

固定日期的完整通知示例在[示例目录](../examples/delivery/README.md)。一次复制一条进行整理，不要把目录说明、多个分隔标题一起粘贴。AI输出须与原文核对，不保证每次措辞完全一致。

**跑通标志**：原文保留，预览分类与时间正确，确认后才能在待办/日程看到。这个入口直接确认创建待办，不是QQ群待确认卡片。

### 不连QQ也能准备收件箱示例

1. 配置密钥后，在“今日”点右上角“＋→粘贴通知原文”。
2. 来源群填写“演示通知”，发布人可填“演示负责人”。将[01-activity.txt](../examples/delivery/01-activity.txt)的正文复制到“通知原文”。
3. 点击“保存并自动整理”。原文会先保存，整理成功后到“收件箱→待确认”查看卡片；未完成或失败时从待处理入口查看。
4. 再分别粘贴考试、竞赛示例，就能左右拖动多张卡片并决定是否加入待办。

这条入口需要网络和AI密钥，但不需要电脑QQ接入。录屏时可以明确说“用粘贴通知演示整理流程”，不要把它描述成QQ群实时自动接收。

## 四、导入示例课表并验证重叠

1. 下载[公开课表示例](../examples/delivery/demo-courses.ics)，传到手机“下载”文件夹。GitHub文件页应下载原始文件，不要将网页HTML另存为ICS；也可从教程压缩包中直接取`demo-courses.ics`。文件中只有两次虚构课程。
2. 在“今日→课程管理→导入课表”或“添加→导入课表”打开导入入口，选择“选择ICS / WakeUp文件”。
3. 在系统文件选择器中选取`demo-courses.ics`。先核对预览：

| 课程 | 日期 | 时间 | 地点 |
| --- | --- | --- | --- |
| 【演示课】图像处理基础 | 2026-10-26 | 10:10—11:50 | 教学楼B202 |
| 【演示课】工程制图 | 2026-10-27 | 14:00—15:40 | 教学楼A102 |

4. 确认导入。到日程选择2026-10-26，并滚动到10:00附近。
5. 第一节课程与前面创建的培训会重叠。点 **10:30—11:50** 的重合处，应能选择查看两条安排；两边的边框仍能对应各自起止时间。
6. 切到月视图，查看26日、27日的课程与事项。

示例年份固定为2026。若文件日期已过，课程会按下课时间更新状态，仍在对应日期的日程中显示；“显示已完成事项”主要控制其他已完成事项。不要因为今天没有课就反复导入。重复导入同一文件会保留已有记录及修改。

**跑通标志**：预览有2次课程，导入后课程和培训会共用同一张日程表，重合处可选择查看。

## 五、配置电脑端QQ接入

### 1. 准备环境

- Windows电脑和Python 3；Android Platform-Tools中有`adb.exe`。
- 使用源码目录。若下载完整交付ZIP，先进入其中的`source/`。
- 从[NapCat官方固定版本](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41)取得`NapCat.Shell.Windows.Node.zip`，解压到`.codex/napcat-desktop/runtime/`；目录内应有`node.exe`、`index.js`和`napcat/`。
- 手机开启开发者选项/USB调试，连接数据线，由本人允许电脑调试；从托盘退出普通电脑版QQ，手机QQ保持登录。

```powershell
py -3 --version
adb devices -l
```

手机状态应为`device`。`unauthorized`需要在手机上允许调试；设备为空时检查线材、USB模式、驱动和调试设置。

### 2. 启动并由本人登录

```powershell
py -3 tools/napcat-desktop/desktop.py start
```

脚本自动选择唯一已授权手机，并建立USB转接；首次启动生成本机独立口令。也可以双击`tools/napcat-desktop/start-demo.bat`。

多设备或SDK不在默认位置时：

```powershell
py -3 tools/napcat-desktop/desktop.py start --serial YOUR_SERIAL --adb "D:\Android\Sdk\platform-tools\adb.exe"
```

需要扫码时，在电脑打开`.codex/napcat-desktop/runtime/napcat/cache/qrcode.png`，用手机QQ扫描并确认。旧登录过期就重新扫码；二维码不是项目展示图片，不要提交或录屏分享。

### 3. 填写手机口令并关注群

1. 在电脑本地打开`.codex/napcat-desktop/local-secrets.json`，取`onebot`字段。不要复制整个JSON，也不要用`webui`字段。
2. 手机“信息与待办→设置→QQ连接”，填入“本机连接口令”，点“保存并连接”。
3. 检查电脑状态：

```powershell
py -3 tools/napcat-desktop/desktop.py status
adb reverse --list
```

预期QQ online为True，USB映射包含手机`tcp:3000`到电脑`tcp:13001`。仅有在线和群数量还不能证明消息已接收。

4. 在手机“信息与待办→关注群”搜索测试群，关注成功后再发新消息。先发后关注的历史消息不作为这次接入验证。

### 4. 验证一条真实新通知

由本人选择合适的测试群，自行发送[01-activity.txt](../examples/delivery/01-activity.txt)的内容。不要代别人发消息，也不要向无关真实群发送虚构通知。

1. 等待手机接收和AI整理，不要反复发送同一条。
2. 在“收件箱→待确认”核对新卡、来源、要求和完整原文。
3. 如果想体验左右连续滑动，可再由本人依次发送[考试](../examples/delivery/02-exam.txt)、[竞赛](../examples/delivery/03-contest.txt)示例。
4. 选一张点“加入待办”。成功后下一张补位；到相应日期查看日程。
5. 可演示另一张“不加入待办”，它进入“已忽略”，可恢复；滑动本身不会提交决定。

如果第二节本地体验已创建同一培训会，不要再同时接收一份相同样例；可换用考试或竞赛示例。不同入口会产生独立事项，不会因为标题相同而自动合并。

**跑通标志**：新通知有原文、AI整理完成、进入待确认，用户确认后进入待办和正确日期的日程。

## 六、更多可复制示例与预期

参见[全部示例及预期结果](../examples/delivery/README.md)：

- 活动、考试、竞赛：完整日期及起止区间。
- 作业：截止时间点，不编造结束时间。
- 只有日期：加入待办后显示在当天未定时区/月表顶部。
- 日期未知：仍可作为普通待办管理，不强行塞进某一天。

## 七、常见问题

| 现象 | 优先检查 |
| --- | --- |
| 手机没有待确认卡片 | 手动新建/口头记忆直接创建待办；QQ群新通知或“粘贴通知原文”经自动整理后进入待确认。新安装默认无样例 |
| 日期在明天，今天没看见 | 查看对应日期框，或在日程日期选择器中选择实际日期 |
| 课表看起来为空 | 核对是否选中示例日期、是否确认导入；已下课课程仍会显示，只是状态更新 |
| 起止时间不完整 | 核对输入法文字、原文和预览，不把只给一个时刻的事项强制当区间 |
| AI整理失败 | 检查手机网络、密钥、API余额；原文在待处理时可重试 |
| QQ在线但没有新卡 | 确认手机口令、USB映射、关注已成功，且消息在关注之后发送；没有可执行事项也可能不生成卡片 |
| 重复登录/身份失效 | 从托盘退出普通电脑版QQ；NapCat需要时由本人重新扫码 |
| USB拔插后不能收信 | 重新执行`desktop.py link`，自定义--serial/--adb时沿用相同参数 |
| APK覆盖安装失败 | 核对签名，不卸载或清空有真实数据的应用；使用同签名交付APK或独立测试设备 |

演示前先按这份教程走通一次。录屏顺序和旁白见[演示视频脚本](VIDEO.md)。
