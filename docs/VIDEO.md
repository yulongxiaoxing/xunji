# 3—5分钟演示视频脚本

## 要不要录

你提供的活动通知明确要求提交GitHub仓库链接，没有写视频必交。因此建议把视频作为帮助评委理解项目的辅助材料；若组委会另有提交表单要求，以其最新明确要求为准。

先把[运行教程](RUNNING.md)跑通，再录屏。视频展示实际操作，清楚说明当前实现即可，不必制作复杂片头。

## 开录前准备

- 手机开启录屏和免打扰，应用字体保持可读；画面以手机界面为主，电脑配置提前完成。
- 若展示QQ接入，先确认电脑在线、USB映射及手机关注状态；扫码、密钥和接口口令不录入画面。
- 只展示自己的演示数据，避开真实群消息、联系人、个人课表和账号信息。
- 准备两到三张待确认演示卡、一个已确认事项和课表示例。不要为了画面好看清空真实数据库。
- 选定固定演示日期，例如2026-10-26；日程切到该日期，时间轴提前滚到10点附近。
- 保留真实AI等待过程，若剪短等待可标注“等待已缩短”，不要把预置内容当作即时返回。

## 四分钟镜头与旁白

| 时间 | 屏幕操作 | 可以直接使用的旁白 |
| --- | --- | --- |
| 00:00—00:20 | 打开寻迹，停留今日 | “寻迹是一款校园信息与日程应用。它把群里的通知整理成可确认事项，再和课程放到同一张日程表里。” |
| 00:20—00:55 | 用“＋→粘贴通知原文”保存一条示例并展示收件箱；已准备QQ接入时可展示真实新通知 | “这里先用粘贴通知演示。原文会保留，AI提取分类、内容和时间，重要的决定仍由我确认。配置QQ接入后，也能接收关注群的新通知。” |
| 00:55—01:30 | 左右拖动玻璃卡片，查看原文，选一项加入待办 | “卡片可以连续滑动查看。滑动不会替我接收或拒绝，确认成功后下一项补位，原文也一直保留。” |
| 01:30—02:10 | 口头记忆输入培训会原句，整理，核对日期与08:30—11:30；可只展示预览，避免再创建重复事项 | “我也可以直接输入自然语言。比如这句话会先判断为活动，再确定实际日期和起止时间，核对之后才保存。” |
| 02:10—02:35 | 今日页面查看按日期组织的课程与待办 | “今日把课程和其他事项按实际日期放在一起，往下就能看到明天和后续已有安排。” |
| 02:35—03:10 | 导入ICS文件，核对2次课程再确认；若已导入，展示课程管理并说明已导入 | “课程可以从文件预览后导入，保留名称、教室、老师和起止时间，不必逐节重新录入。” |
| 03:10—03:45 | 周表选择10月26日，点10:30—11:50重合处，查看课程与培训会 | “周表按真实时刻显示。重叠的安排叠放呈现，点击重合时段可以分别查看，方便发现时间冲突。” |
| 03:45—04:10 | 切换月表，纵向滚动，停留有事项的日期 | “月表直接列出每天的事项与时间，没有时刻的放在当天顶部。从消息到决定，再到可视化日程，这就是寻迹现在的完整流程。” |

## 录制取舍

- QQ或网络不稳定时，先录已经跑通的本地操作；把“接收演示数据”和“现场实时收信”区分说明。
- 如果要压到3分钟，缩短片头、输入和文件选择等待，保留“核对原文→确认→日程”的完整闭环。
- 不必逐页读设置和源码；完整运行步骤已经放在README与运行教程中。
- 视频最后停在可视化日程表，展示已实现的结果即可。

提交时优先保留GitHub仓库和Release下载地址；视频可作为附件或独立链接补充。上传到视频平台前，再检查一遍隐私与可访问权限。
